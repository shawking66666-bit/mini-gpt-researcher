# Mini GPT Researcher 产品化前端 V1 设计稿（已确认：最小 MVP）

## 目的与定位

为现有深度研究 Agent 增加一套独立网页前端，同时产出可用于 AI 产品经理作品集的需求说明、交互原型与验收证据。重点是展示从用户问题到可用交互的产品设计能力，而不是重做已存在的研究/RAG 后端。

**目标用户（本稿暂定）：** 需要同时参考公开网页与自己 PDF/Markdown 资料、并希望检查报告来源的个人研究者或产品需求分析者。第一版按本地单用户使用设计；“AI 产品经理作品集”是展示用途，不等于产品只供招聘者使用。

**核心任务：** 上传一份可提取文字的非敏感文档 → 输入研究主题并执行“混合检索” → 等待研究完成 → 阅读报告、查看对应证据并下载结果。新前端 V1 只呈现混合检索；后端现有的“仅联网”和“仅文档”能力不删除，后续再决定是否放入新页面。

## 已选方案与取舍

先前讨论过：继续改 Streamlit，或做独立网页前端。用户选择后者。第一版建议使用 React + TypeScript + Vite 作为独立客户端，复用现有 FastAPI 接口；现有 Streamlit 保留为开发演示入口，不在本轮删除或重写。独立客户端增加一套前端构建与测试成本，但能更准确地落地页面层级、交互状态和视觉规范。

备选的“只做静态原型”不足以证明与真实后端闭环；备选的“同时重构后端任务队列”会扩大范围，留待后续版本。

## V1 交付物

1. **简版 PRD：** 用户、问题、场景、范围、主流程、字段和验收标准；明确哪些是已有能力、哪些是本轮新增。
2. **可检查的交互原型：** 由实际可点击的新前端承担；另附页面结构、按钮行为、状态转换和接口映射说明，不额外维护一套会与代码脱节的静态原型。
3. **独立网页前端：** 浅色专业研究报告风格，桌面优先，手机宽度下能完成主流程；连接真实本地 FastAPI。现有 Streamlit 不变。
4. **验证材料：** 前端构建/测试、后端原测试、浏览器中的上传→混合研究→结果查看演示、非敏感截图与已知限制。

## 信息架构和关键交互

单页研究工作台分成三个清晰区域：

- **新建研究：** 主题输入、文件选择，页面明确标记“混合检索”；对上传限制提前提示（1–5 个 PDF/Markdown，单文件 10 MiB，总计 30 MiB）。上传完成并得到就绪的 `knowledge_base_id` 后才能发起研究。
- **运行反馈：** 上传、研究各自有禁用重复提交的加载状态；展示服务端返回的实际错误。当前 `POST /research` 同步执行，V1 只能显示通用“研究正在运行”，不能伪造 Planner/Search/Reflector 的实时进度条。
- **研究结果：** 报告为主视图；研究计划、Evidence 来源、任务/用量为可切换区域。网页证据能打开 URL，文档证据展示文件名/页码；报告可下载 Markdown/HTML。明确提示“引用编号存在不代表结论已被原文验证”。

空状态、输入不合法、上传失败、知识库未就绪、研究失败、无报告、网络不可达都要有可读提示和下一步操作。V1 不展示虚构的成本节省或准确率数据。

## 接口和数据边界

- `POST /knowledge-bases`：多文件上传；成功返回 `knowledge_base_id`、文档数、切块数。前端仅保存本次会话所需 ID，不保存用户原文到浏览器长期存储。
- `POST /research`：请求包含 `topic`、固定的 `retrieval_mode="hybrid"` 和 `knowledge_base_id`；返回完整 `ResearchState`。创建失败与返回 `status=failed` 是两种不同情形，前端分别处理。
- 后端现有 `GET /research/{task_id}` 与 `/report` 保持不变，但新页面 V1 不提供历史列表或跨浏览器“我的历史”，因为后端没有用户身份或权限隔离。
- 前端本地开发端口和后端 `8000` 属不同来源；实现计划须选定开发代理或明确来源的 CORS 配置，不开放无限制跨域。真实 API 密钥只留在后端环境，不进入前端代码、构建产物或浏览器存储。

前端只消费现有 JSON 契约；若发现确实缺字段，先记录需求和兼容性影响，再决定是否修改 API。不得把扫描版 PDF、账号体系、权限隔离、OCR、异步任务队列、生产部署悄悄塞进 V1。

## 验收标准

1. 用户用非敏感 Markdown/PDF 完成上传，页面显示成功状态和文件摘要；无效格式、超限文件有可理解提示。
2. 用户选择混合检索并输入主题，前端只发一次研究请求；完成后能读取报告、计划和至少一条来源；失败时不把错误伪装为成功。
3. 页面上的来源类型、编号、文档名/页码与 API 返回一致；下载的 Markdown/HTML 与报告内容一致。
4. 桌面和手机窄屏都能完成同一条主流程；键盘可操作主要控件，表单有标签，加载/错误状态可被识别。
5. 前端构建与基础交互测试通过，现有 Python 测试不回退；浏览器手工验收记录实际结果与未验证项。截图只用非敏感演示资料。

## 实施前规则与非目标

现有 `CLAUDE.md` 尚未为独立前端和产品设计材料约定目录。**获批后第一步先更新该规范**，规定前端源码、PRD、原型和截图放置位置及清理规则，再建立目录和写代码。不得修改 `.env`、密钥、CI/CD、数据库 schema 或推送 GitHub，除非获得对应授权。

本轮不替换 Streamlit、不在新页面加入三模式切换、不增加聊天机器人、不引入多用户协作或生产发布，也不同时改造 AI-Ad-QA 项目。作品集叙述应区分“原型”“本地可运行功能”“真实服务冒烟测试”和“生产交付”。

## 留给实施计划决定

组件与样式实现、具体页面路由、测试工具和开发代理的细节，可在不改变上述产品行为的前提下由实施计划选择。选择应以最少依赖、可读代码和后端契约复用为准，并记录理由。
