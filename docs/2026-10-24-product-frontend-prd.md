# Mini GPT Researcher 独立前端 V1 PRD

## 用户与问题

目标用户是本地单人研究者或产品需求分析者：手上有可提取文字的 PDF/Markdown，需要把私有资料和公开网页一起纳入研究，并能回查结论引用。现有后端已具备混合检索、报告和来源编号；本版新增可操作的网页入口及清楚的结果呈现。

## 核心用户故事

作为研究者，我上传 1–5 份资料、输入研究主题并发起混合研究，完成后阅读报告、查看计划和来源、下载 Markdown/HTML，以便判断哪些结论值得进一步核实。

## 范围与流程

1. 输入非空主题，选择 PDF/Markdown。每份不超过 10 MiB，总计不超过 30 MiB。前端先提示，后端最终校验。
2. 点击“开始混合研究”后，先调用 `POST /knowledge-bases`。成功且 `status=ready` 才使用返回的 `knowledge_base_id` 调用 `POST /research`，请求体为 `topic`、`retrieval_mode: hybrid`、`knowledge_base_id`。
3. 上传时显示“正在上传资料”，研究时显示“正在研究，请稍候”；按钮禁用，避免重复提交。研究接口同步返回，因此不展示虚假的内部阶段进度。
4. 只有 `ResearchState.status=completed` 且 `report` 非空，才显示报告。报告优先，另可查看研究计划、网页/文档来源及任务用量。保留原始来源编号和文档页码。
5. Markdown/HTML 下载取自返回的 `ResearchReport`。引用编号合法仅表示编号存在，不保证结论已得到原文语义支持。

## 状态与异常

| 状态 | 页面行为 |
| --- | --- |
| 空状态 | 说明需输入主题并选文件；不发请求 |
| 输入不合法 | 就地提示主题、文件数量、格式或大小；不发请求 |
| 上传中/研究中 | 标明当前操作，禁用重复提交 |
| 上传失败/知识库未就绪 | 展示可读错误，可修改输入后重试；不发研究请求 |
| HTTP 422/503 或网络异常 | 展示安全且有下一步的错误，不把响应渲染为报告 |
| 任务 `failed` 或无报告 | 展示失败/无报告状态，不显示“完成” |
| 成功 | 展示报告、计划、来源和下载操作 |

## 验收

- 在桌面和手机窄屏可完成同一条主流程；主题、文件控件有标签，键盘可操作，加载/错误文本可识别。
- 一次点击只上传一次、研究一次；无效输入不请求后端；接口异常不会变为成功界面。
- 页面与下载保留 API 原报告和来源信息；报告 Markdown 中的原始 HTML 不执行。
- 前端测试和构建、现有 Python 测试通过；浏览器演示使用非敏感资料，并注明是否调用了真实付费服务。

## 非目标

不做登录、多人隔离、扫描 PDF OCR、历史任务列表、异步队列、生产部署，也不在 V1 页面开放仅网页/仅文档模式。现有 Streamlit 和后端三种检索模式继续保留。
